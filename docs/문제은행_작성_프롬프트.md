# 문제 은행 확장 작업 프롬프트

> 아래 전체를 새 세션에 붙여넣고, `문제은행_v1.xlsx`를 함께 첨부하십시오.
> 그 세션은 www.kipi.or.kr 에 접근할 수 있어야 합니다.

## 작업 요청

첨부한 `문제은행_v1.xlsx`를 이어받아, **www.kipi.or.kr 을 직접 조사해서 문제 은행을 200문항으로 확장하고 기존 문항을 현행 기준으로 검수**해 주세요.

### 1. 이 문제 은행이 무엇에 쓰이나

한국특허정보원 사내 e-sports 행사용 웹게임 **「민원 연결의 神」**의 게임 데이터입니다.

게임은 이렇게 굴러갑니다. 화면 왼쪽에 민원인이 한 마디를 던지면(예: *"연도별 특허 출원 건수 통계를 보고 싶습니다"*), 오른쪽에 뜬 사업/부서 버튼 중 담당하는 곳을 고릅니다. 제한시간 180초 동안 최대한 많이, 정확하게 연결하는 것이 목표입니다. 틀리면 0.7초간 멈추면서 **정답 부서와 한 줄 해설이 화면에 그대로 표시**되고, 게임이 끝나면 틀린 문항이 부서별로 묶여 리뷰 화면에 나옵니다.

즉 이 문제 은행은 단순한 퀴즈 데이터가 아니라 **"전사 임직원이 타 부서 업무를 자연스럽게 알게 되는" 행사 목적을 실제로 달성하는 유일한 장치**입니다. 문항이 부정확하면 참가자에게 틀린 지식을 심어주게 되므로, 정확도가 재미보다 우선입니다.

### 2. 왜 200문항이 필요한가

- 1판 180초에 문항이 **50~60개** 소비됩니다
- 대회 규정상 1인 3회까지 플레이 → **150~180문항**이 노출됩니다
- 그 이하로는 두 번째 판부터 같은 문항이 반복돼 체감 품질이 급락합니다

현재 **100문항**이 확보돼 있으므로 **100문항을 추가**해야 합니다.

### 3. 기존 100문항의 한계 (반드시 확인 필요)

기존 문항은 **2020년 10월 발행 브로슈어**와 홈페이지 주요사업 **메뉴 구조**만 보고 작성했습니다. 작성 세션이 www.kipi.or.kr 에 접속할 수 없어 각 사업의 상세 페이지를 읽지 못했습니다. 따라서:

- 조직 개편이나 사업 변경이 반영돼 있지 않을 수 있습니다
- 분류 체계 14개가 현행 사업 구분과 어긋날 수 있습니다
- 개별 문항의 정답이 현재 기준으로 틀렸을 수 있습니다

**이번 작업의 첫 단계는 신규 작성이 아니라 기존 문항 검수입니다.**

## 수행할 작업 (순서대로)

### 1단계 — 현행 사업 체계 조사

www.kipi.or.kr 의 **주요사업** 하위 페이지를 모두 읽고, 각 사업의 실제 업무 범위를 정리하세요. 확인된 메뉴 구조는 다음과 같습니다(변경됐을 수 있으니 실제 사이트 기준으로 갱신):

- **지식재산정보 활용촉진** — 지식재산정보 검색서비스 제공 / 국내외 지식재산권 데이터베이스 구축 / PCT 국제출원문서 번역서비스 제공
- **지식재산정보산업 육성·지원** — 지식재산정보 활용서비스 제공 / 유관기관 IP정보시스템 통합 운영·관리 / 지식재산 정보화 R&D / 지식재산 정보화 국제협력 / 국제특허정보박람회
- **특허행정 정보화 및 업무지원** — 특허넷 시스템 운영 / 특허고객 상담서비스 제공
- **지식재산 기술지원** — 기술이전 / 보유기술목록 / 기술홍보자료 / 최신기술동향

조직안내 페이지가 있다면 함께 확인해, **분류 단위를 "사업"으로 둘지 "부서"로 둘지** 판단해 주세요. 현재는 사업 단위입니다.

### 2단계 — 기존 100문항 검수

`문제은행` 시트의 각 행을 1단계 조사 결과와 대조하고, `검수상태` 열을 갱신하세요.

- `검수완료` — 정답이 현행 기준으로 맞음
- `보류` — 사이트에서 확인 불가. **사유를 비고로 남길 것**
- 정답이 틀렸으면 `정답 분류`·`해설`·`출처`를 고치고 `검수완료`로 변경

### 3단계 — 신규 100문항 작성

아래 작성 규칙에 따라 추가하세요.

### 4단계 — 난이도 재조정

현재 난이도 1:2:3 = **25:46:29**입니다. 목표는 **40:40:20**입니다. 신규 문항으로 균형을 맞추되, 난이도를 억지로 끼워 맞추지 말고 실제 체감 난도로 매긴 뒤 결과를 보고하세요.

## 작성 규칙

### 열 정의

| 열 | 규칙 |
| --- | --- |
| `문항ID` | `c101`부터 이어서 부여 |
| `민원 내용` | 민원인이 실제로 할 법한 1인칭 구어체. **40자 이내** |
| `정답 분류` | `분류체계` 시트의 항목 중 하나 |
| `오답후보1~3` | 실제로 헷갈리는 분류. 1개 이상 권장 |
| `해설` | 왜 그 분류인지 한 줄. **45자 이내** |
| `난이도` | 1 / 2 / 3 |
| `사업영역` | 분류체계 시트의 상위 사업영역 |
| `출처` | **직접 확인한 URL 또는 페이지명** |
| `검수상태` | 미검수 / 검수완료 / 보류 |

### 좋은 문항을 만드는 요령

**① 민원 문장에 정답을 적지 마세요.**
`"통계 서비스에 문의합니다"` 처럼 사업명을 그대로 넣으면 업무를 아는지 묻는 문제가 아니라 글자를 읽는 문제가 됩니다. 대신 **민원인이 겪는 상황**을 쓰세요.

- ✗ `"지식재산 통계서비스가 필요합니다"`
- ✓ `"연도별 특허 출원 건수 통계를 보고 싶습니다"`

**② 오답후보는 진짜 헷갈리는 것으로.**
무관한 분류를 넣으면 난이도가 무너집니다. "이 민원을 받은 신입 직원이 실제로 잘못 보낼 만한 곳"을 넣으세요.

- 검색 관련 민원 → KIPRIS ↔ KIPRISPlus ↔ 데이터관리센터
- 영문 관련 민원 → 영문초록(KPA) ↔ 번역서비스
- 시스템 장애 민원 → 특허넷 운영 ↔ IP정보통합센터

**③ 해설은 게임 화면에 그대로 뜹니다.**
참가자가 0.7초 안에 읽고 이해할 문장이어야 합니다. 근거를 한 줄로 압축하세요.

- ✓ `"국내외 39개 기관 특허데이터를 수집해 DB로 구축합니다."`
- ✗ `"해당 업무는 관련 규정에 따라 소관 부서에서 처리합니다."` (아무것도 알려주지 않음)

**④ 난이도 기준**

| 난이도 | 기준 | 예 |
| --- | --- | --- |
| 1 | 업무 성격이 문장에 거의 드러남 | `"특허를 무료로 검색할 수 있는 사이트가 있나요?"` |
| 2 | 유사 사업과 혼동 가능 | `"관심 기술의 신규 특허를 메일로 받고 싶습니다"` |
| 3 | 세부 업무 지식 필요 | `"LOD 방식으로 데이터를 연계하고 싶습니다"` |

**⑤ 분류별로 고르게.**
한 분류에 최소 10문항을 목표로 하세요. 특정 사업에 몰리면 그 사업만 반복 노출됩니다.

### 하지 말아야 할 것

- **추정으로 쓰지 마세요.** 사이트에서 확인되지 않는 사업명·서비스명·수치를 쓰면 안 됩니다. 확인이 안 되면 `보류`로 두고 사유를 남기세요.
- **실제 민원 사례를 그대로 옮기지 마세요.** 이 데이터는 공개 저장소에 올라갑니다. 개인·기업을 특정할 수 있는 내용은 제외하세요.
- **특정 부서를 부정적으로 묘사하지 마세요.** 사내 행사용입니다. 민원인의 불만은 상황 묘사까지만 하고 부서 비난으로 읽히지 않게 쓰세요.
- **법령을 인용할 때는 조문 번호와 출처를 표기하세요.**

`문제은행_v1.xlsx`와 **동일한 열 구조**로 다음을 제출해 주세요.

1. `문제은행` 시트 — 기존 100행의 `검수상태`가 갱신되고, 신규 100행이 추가된 상태
2. `분류체계` 시트 — 현행 사업 기준으로 갱신 (분류를 바꿨다면 근거 URL 명시)

### 제출 전 자가 점검

- [ ] `정답 분류`·`오답후보`가 모두 `분류체계` 시트에 등록된 값인가

- [ ] 같은 취지의 중복 문항이 없는가
- [ ] 분류별 문항 수 편차가 크지 않은가
- [ ] 모든 신규 문항에 **확인한 출처**가 적혀 있는가

## 참고 — 게임 반영 방법

엑셀이 원본이고, 게임 데이터는 여기서 생성됩니다. 수동으로 TS 파일을 고치지 마세요.

```bash
python3 scripts/build_bank.py    # 엑셀 → frontend/src/data/{departments,complaints}.ts
```

이 스크립트에는 작성 규칙 자동 검사가 들어 있어, 미등록 분류·정답과 중복된 오답후보·글자수 초과가 있으면 생성이 중단되고 해당 행을 알려줍니다. 제출 전에 한 번 돌려보면 점검이 끝납니다.
